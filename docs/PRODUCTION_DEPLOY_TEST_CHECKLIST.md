# Production Deploy Test Checklist

## 목적

- 실서버 배포 직후 현재 구현 범위(`Stage 1`, `Stage 2`, `Stage 3`, `Stage 5`, `Stage 6`, `Phase 2`, `Phase 3`)가 정상 동작하는지 점검한다.
- 이번 체크리스트는 `Phase 4 챗봇` 이전 범위만 다룬다.
- `Stage 4 회계 대시보드 RPA`는 현재 범위 제외로 본다.

## 사전 준비

- 운영용 `DB`, `JWT`, `AI`, `RPA` 환경변수가 모두 반영되었는지 확인
- 백엔드, 프론트, AI 서버, RPA 서버 프로세스가 모두 기동되었는지 확인
- 운영 관리자 계정 1개, 재고 담당 계정 1개, 인사 담당 계정 1개 준비
- RPA 결과 저장 경로와 callback 토큰이 운영 환경값으로 반영되었는지 확인
- 브라우저 캐시를 비우거나 시크릿 창으로 접속

## 1. 공통 기동 점검

- 로그인 페이지 진입 확인
- 관리자 계정 로그인 성공 확인
- 잘못된 비밀번호 로그인 실패 확인
- 새로고침 후 세션 유지 확인
- 로그아웃 동작 확인
- 백엔드 기본 API 응답 확인
- AI 서버 health 확인
- RPA 서버 health 확인

## 2. 권한/메뉴 점검

### 관리자 계정

- `system-admin` 진입 확인
- `task-history` 진입 확인
- `anomaly-detection` 진입 확인
- RPA 관련 버튼/요약 카드 노출 확인

### 재고 계정

- `inventory/dashboard` 진입 확인
- `inventory/purchase-dashboard` 진입 확인
- `inventory/reorder` 진입 확인
- 관리자 전용 RPA/이상탐지 메뉴가 숨김 또는 차단되는지 확인

### 인사 계정

- `hr/payroll/list` 진입 확인
- 관리자 전용 메뉴 접근 차단 확인

## 3. Stage 1 공통 RPA 트리거 점검

- 관리자 화면에서 RPA 트리거 실행 가능 확인
- 트리거 후 task history 에 새 실행 이력이 생성되는지 확인
- 실행 중 상태가 보이는지 확인
- 성공 시 `SUCCESS` 상태 반영 확인
- 실패 시 에러 메시지 또는 실패 상태 반영 확인
- 최근 실행 이력 조회가 최신순으로 보이는지 확인

## 4. Stage 2 구매/발주 대시보드 점검

- `purchase-dashboard` 진입 확인
- 구매 RPA 실행 버튼 동작 확인
- 최근 수집 결과 카드 표시 확인
- ERP 기준가 / 수집가 / 차이 표시 확인
- 결과 파일 파싱 실패 없이 화면에 반영되는지 확인
- 비관리자 자동 호출 문제가 없는지 확인

## 5. Stage 3 재고 대시보드 점검

- `inventory/dashboard` 진입 확인
- 재고 부족 조회형 RPA 실행 확인
- 부족 품목 경고 카드 표시 확인
- 기존 재고 차트/통계와 충돌 없이 같이 보이는지 확인
- 최근 실행 이력과 결과 요약이 연결되는지 확인

## 6. Stage 5 인사/급여 점검

- `hr/payroll/list` 진입 확인
- 최저임금/기준정보 조회 RPA 실행 확인
- 최신 기준 정보 카드 표시 확인
- ERP 급여 기준값과 비교 UI가 정상 표시되는지 확인
- 권한 없는 계정에서 관리자 전용 호출이 발생하지 않는지 확인

## 7. Stage 6 운영 UX 점검

- 각 RPA 카드에 최근 실행 이력이 보이는지 확인
- 실패 실행 후 재시도 버튼 또는 재실행 동선 확인
- callback 지연 시 실행 중 상태가 유지되는지 확인
- 성공/실패/진행중 표시 문구가 자연스러운지 확인
- task history 필터가 다른 시나리오 이력과 섞이지 않는지 확인

## 8. Phase 2 이상 탐지 점검

- `anomaly-detection` 페이지 진입 확인
- 목록 조회 성공 확인
- `refresh` 실행 시 이상 로그 재생성 확인
- 다음 규칙이 실제 데이터에 맞게 잡히는지 표본 확인
- `NEGATIVE_CURRENT_STOCK`
- `NEGATIVE_AVAILABLE_STOCK`
- `OUT_OF_STOCK_WITH_SAFETY`
- `REORDER_VENDOR_MISSING`
- `STOCKOUT_BEFORE_LEAD_TIME`
- 상태 변경(`OPEN`, `CONFIRMED`, `FALSE_POSITIVE`, `IGNORED`) 저장 확인
- 시스템 운영 화면에서 이상 탐지 진입 링크 정상 동작 확인

## 9. Phase 3 추천 발주 점검

- `inventory/reorder` 페이지 진입 확인
- 추천 목록 조회 성공 확인
- 요약 카드(`추천 가능`, `수동 검토`, `비활성`, `긴급 품목`) 숫자 확인
- 상태 필터 동작 확인
- 긴급 필터 토글 on/off 확인
- `READY` 항목은 발주 요청 버튼이 활성화되는지 확인
- `DISABLED` 항목은 비활성 사유가 보이는지 확인
- `REVIEW` 항목은 수동 검토 메시지가 보이는지 확인
- 최근 30일 출고, 출고일 수, 리드타임, 발주 근거 건수가 표시되는지 확인
- 예약재고가 큰 품목에서 추천 수량이 과소 계산되지 않는지 표본 확인
- 신규 추천 API 실패 시 legacy fallback 화면으로 최소 표시가 되는지 확인

## 10. 운영 로그/보안 점검

- 백엔드 로그에 stack trace 대량 노출이 없는지 확인
- 프론트 콘솔에 401/403/500 반복 호출이 없는지 확인
- RPA 결과 파일 접근이 허용된 경로로만 제한되는지 확인
- 운영 설정 파일에 테스트 토큰/테스트 DB 값이 남아있지 않은지 확인
- 민감정보가 API 응답이나 로그에 그대로 출력되지 않는지 확인

## 11. 데이터 무결성 점검

- task history 적재가 중복 없이 되는지 확인
- anomaly log 갱신 후 활성/비활성 상태가 의도대로 유지되는지 확인
- 추천 발주 조회가 재고 데이터를 변경하지 않는지 확인
- RPA 실패가 ERP 핵심 테이블 변경으로 이어지지 않는지 확인

## 12. 장애 대응 체크

- RPA 서버 중단 시 프론트/백엔드 에러 메시지 확인
- AI 서버 중단 시 기존 AI 기능만 영향받고 ERP 기본 기능은 유지되는지 확인
- callback 실패 시 운영자가 이력을 보고 재시도할 수 있는지 확인
- 잘못된 권한 계정 요청이 403 으로 막히는지 확인

## 최종 승인 기준

- 관리자/재고/인사 주요 화면 진입과 권한이 모두 정상
- Stage 1, 2, 3, 5, 6 시나리오가 최소 1회 이상 성공
- Phase 2 이상 탐지 목록/상태 변경 정상
- Phase 3 추천 발주 상태/근거/버튼 동작 정상
- 치명적 로그, 500 오류, 권한 누수, 잘못된 자동 호출 없음

## 배포 후 기록 권장

- 점검 일시
- 점검자
- 사용한 계정 역할
- 성공/실패 항목
- 실패 항목의 재현 단계
- 관련 로그 파일 위치
- 즉시 조치 여부
